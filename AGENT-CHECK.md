# Repository Quality Check Instructions

> **Purpose**: This document provides detailed instructions for AI agents to perform comprehensive quality assurance checks on the Logos Eco Dev wiki repository.

## Overview

When the user says "check", perform the following quality assurance tasks across the repository.

**IMPORTANT**: When running checks, always exclude the `tmp/` directory.

---

## Check Tasks

### 1. Ensure Filename Conventions

Verify that all markdown files follow naming best practices:

- Use underscores instead of spaces (e.g., `sample_apps.md` not `Sample Apps.md`)
- Filename should closely match the `title` frontmatter property (lowercase, underscores, reasonable length)

### 2. Validate Internal Links

Check that all existing wikilinks in the repository point to valid files that exist.

**Process:**

1. Extract all wikilink paths from markdown files
2. For each unique path, verify the corresponding file exists
3. Report any broken links with file location and expected path

### 3. Validate Wikilink Titles

Ensure that wikilink display text matches (or is a reasonable contextual abbreviation of) the `title` frontmatter property of the linked file.

### 4. Verify AI-Generated Content Disclaimer

**CRITICAL**: Ensure all LLM-generated files in the `content/` folder carry the AI disclaimer.

**Check for:**

- LLM-generated markdown files in `content/` should have the `> [!ai-generated]` indicator
- This applies to ALL content types: processes, protocols, guides, and any other generated documents
- Indicator should be placed immediately after frontmatter and description (for whole-file) or after section headers (for partial)

**Recommended pattern (whole-file):**

```markdown
---
title: Document Title
---

Brief description.

> [!ai-generated]
> This entire document was generated by an LLM and has not yet been human-reviewed.

## First Section

...
```

**What to report:**

- Files missing AI disclaimer
- Files with incorrectly placed disclaimers

## Automated Check Commands

The following bash commands can be used to automate quality checks:

### 1. Check for Files with Spaces in Names

```bash
find . -name "*.md" -type f -name "* *" -not -path "*/tmp/*"
```

**Expected output:** Empty (no files with spaces)

### 2. List All Markdown Files with Titles and Filenames

```bash
find . -name "*.md" -type f -not -path "*/tmp/*" -exec sh -c '
  for file; do
    title=$(grep -m1 "^title:" "$file" 2>/dev/null | sed "s/title: *//")
    filename=$(basename "$file" .md)
    if [ -n "$title" ]; then
      echo "$file | Title: $title | Filename: $filename"
    fi
  done
' sh {} +
```

**Use:** Review to ensure filenames closely match titles (with reasonable abbreviations)

### 3. Extract All Unique Wikilinks

```bash
grep -roh "\[\[[^]]*\]\]" content/ --include="*.md" --exclude-dir=tmp | sort -u
```

**Use:** Review all wikilinks for correctness and consistency

### 4. Validate Wikilink Paths Exist

```bash
# Extract unique wikilink paths (strip display text and #anchors), then check the file exists under content/
grep -roh "\[\[[^]]*\]\]" content/ --include="*.md" --exclude-dir=tmp | \
  sed 's/\[\[\([^]|#]*\).*/\1/' | sort -u | while read link; do
  [ -z "$link" ] && continue
  if [ ! -f "content/${link}.md" ] && [ ! -f "content/${link}/index.md" ]; then
    echo "BROKEN: $link"
  fi
done
```

**Expected output:** Empty (no broken links) or list of broken wikilinks

### 5. Count Total Markdown Files (Excluding tmp)

```bash
find content -name "*.md" -type f -not -path "*/tmp/*" | wc -l
```

### 6. Find References to a Specific File/Concept

```bash
grep -r "SEARCH_TERM" content/ --include="*.md" --exclude-dir=tmp
```

## Reporting

When reporting check results:

1. **Summary Statistics:** total files analyzed, total wikilink occurrences, unique file paths referenced
2. **Issues Found:** list each type of issue with count and specific examples (file paths)
3. **Issues Fixed:** list what was corrected and note file paths modified
4. **Remaining Issues:** list issues requiring human review or decision, with recommendations
