Development path for building web-based frontend modules using HTML/CSS/JavaScript with the [[integration/infrastructure_essentials/logos_js_sdk|Logos JS SDK]], running within QtWebView in the Logos Launcher.

Potentially, support running in a browser to enable developers to build one web apps, and distribute in both the [[Logos launcher]] as a [[mini app]], and in the browser, as a standard webapp (albeit with some limitations).
## FURPS+

### Functionality
- Enable developers to build frontend modules using web technologies (HTML, CSS, JavaScript)
- Provide access to [[integration/infrastructure_essentials/logos_core|Logos Core]] modules via [[integration/infrastructure_essentials/logos_js_sdk|Logos JS SDK]], JavaScript API
- Frontends runs in [[[Logos launcher]]]
- Support event-driven architecture with listeners for module events
- Allow developers to use modern web frameworks (React, Vue, Svelte)
- Frontend can run in a standard Browser; with partial [[Logos module]] functionalities (e.g wasm-compiled [[Logos Blockchain]], or existing JS implementation of [[Logos Messaging]]).

### Usability
- Familiar web development workflow for JavaScript developers
- Web debugging available in [[Logos Core]]
- Hot-reloading during development
- No Qt/C++ knowledge required
- Access to npm ecosystem and web libraries
- Simple async/await API and event-driven (`EventEmitter`) for calling backend modules
- Seamless run in [[Logos Launcher]] as [[mini app]] and in the browser

### Reliability
- Handling of standard Web APIs is considered; potentially supported

### Performance
- Leverage native OS webview for optimal performance
- Minimal overhead compared to bundled browser engines
- Efficient IPC between JavaScript and Qt backend via Qt WebChannel
- Support for lazy loading, code splitting and tree shaking

### + (Privacy, Anonymity, Censorship-Resistance)

- **Privacy**: Frontend modules inherit privacy features of backend modules they call in [[Logos Launcher]], module can be anonymously loaded from [[Logos Storage]]
- **Security**: Integrity checks when loaded from [[Logos Storage]]
- **Censorship-Resistance**: Modules can be distributed via [[integration/infrastructure_essentials/logos_storage|Logos Storage]]
- Limited security, privacy and censorship-resistance when used in the browser

### Architecture
```
Web Frontend (HTML/CSS/JS)
    ↓ (Qt WebChannel)
QtWebView (embedded in Logos Launcher)
    ↓ (Logos JS SDK)
Backend Modules (wallet, chat, waku, storage)
    ↓ (Qt Remote Objects)
Logos Core
```

### Key Components
- **QtWebView Integration**: Logos Launcher embeds QtWebView to render web-based modules
- **Qt WebChannel Bridge**: Enables bidirectional communication between JavaScript and Qt/C++
- **Logos JS SDK**: JavaScript library providing ergonomic API (`logos.chat.sendMessage()`, `logos.wallet.getBalance()`)
- **Reflective API**: Auto-generated JavaScript bindings for all available module methods
- **Event System**: Subscribe to backend events via `logos.<module>.on<EventName>(callback)`

### Developer Workflow
1. Create HTML/CSS/JavaScript files for frontend UI
2. Import Logos JS SDK in JavaScript code
3. Initialize SDK: `const logos = new LogosAPI()`
4. Call backend modules: `await logos.wallet.getBalance(address)`
5. Listen for events: `logos.chat.onChatMessage((msg) => { ... })`
6. Test locally in QtWebView or browser with mock backend
7. Package module for distribution via [[integration/infrastructure_essentials/logos_storage|Logos Storage]]
8. Load module in Logos Launcher

### Example Code
```javascript
// Initialize Logos JS SDK
const logos = new LogosAPI();

// Call wallet module
const balance = await logos.wallet.ethBalance('0x...');

// Listen for chat messages
logos.chat.onChatMessage((message) => {
  console.log('New message:', message);
});

// Join a chat channel
await logos.chat.joinChannel('general');
```

## Technical Validation

**Risks & Challenges:**
- QtWebView lacks built-in communication mechanism (requires Qt WebChannel fork)
- Maintaining JavaScript SDK in sync with evolving backend module APIs
- Performance overhead of WebView vs native Qt UI
- Limited access to native device APIs compared to Electron/Tauri
- Browser compatibility testing across platforms (uses system WebView)
- Debugging QtWebView embedded apps vs standalone browsers
- Managing module dependencies and versioning

**Requirements:**
- QtWebView with Qt WebChannel support (custom fork: `logos-co/qtwebview/feature/webchannel`)
- [[integration/infrastructure_essentials/logos_js_sdk|Logos JS SDK]] with reflective API
- Logos Launcher with integrated QtWebView runtime
- Module packaging format for web-based modules
- Development tooling and documentation
- Example modules demonstrating common patterns

**Integration Points:**
- [[integration/infrastructure_essentials/logos_core|Logos Core]] for module lifecycle management
- [[integration/infrastructure_essentials/logos_js_sdk|Logos JS SDK]] for backend module access
- QtWebView for rendering web UI
- Qt WebChannel for JavaScript-to-Qt bridge
- [[integration/infrastructure_essentials/logos_storage|Logos Storage]] for module distribution
- Backend modules: wallet, chat, waku, storage, etc.
