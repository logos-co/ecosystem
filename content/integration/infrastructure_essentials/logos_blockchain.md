## FURPS+

### Functionality
- Provide data availability and consensus via Nomos
- Execute smart contracts via Nescience zkVM built on RISC Zero
- Support hybrid state model: account-based (public) and UTXO-based (private) with transparent translation layer
- Offer four user-selectable execution modes per transaction: public, private, shielded (public→private), deshielded (private→public)
- Enable private state transitions with zero-knowledge proofs

### Reliability
- Ensure transaction finality through Nomos consensus
- Provide verifiable execution proofs via RISC Zero
- Maintain operational resilience through low barriers to node participation

### + (Privacy, Anonymity, Censorship-Resistance)

- **Privacy**: Users choose privacy level per transaction; private execution hides transaction details and contract state via ZK proofs
- **Anonymity**: Nomos makes validator contributions indistinguishable, concealing block proposers and disassociating them from their stake; Nescience separates state to prevent identity correlation
- **Security**: Zero-knowledge proofs ensure correctness without revealing data
- **Censorship-Resistance**: Transaction neutrality processes transactions without discrimination; users can recover assets even when actively censored by applications

## Possible Implementation

- **Consensus & DA Layer**: Nomos provides data availability and transaction ordering
- **Execution Layer**: Nescience executes Rust contracts compiled to RISC-V, running in RISC Zero zkVM
- **State Architecture**: Dual-state system with account model for public state, UTXO model for private state, unified by SDK abstraction
- **Proof System**: RISC Zero generates validity proofs for state transitions
